# Pulser
[![SHL-0.51 license](https://img.shields.io/badge/license-SHL--0.51-green)](LICENSE)

Pulser is a SystemVerilog-based hardware project designed to generate precisely timed output pulses with configurable parameters. It includes a complete RTL implementation, a simulation environment and autogenerated register files.
Each pulser can be configured and controlled via the Open Bus Interface (OBI).

## Features

- Parameterizable pulse generator
- Register-mapped configuration interface
- Configurable pulses
- Software-controllable start and stop
- Simulation testbench for `pulser_core`
- Register definition autogenerated from HJSON config files

## Architectural Overview

The design revolves around two main modules:

- **pulser** – The top-level module that integrates the core pulse generation logic, register files and serves as the primary interface to the system. It manages control signals and orchestrates the behavior of the pulser_core.
- **pulser_core** – Implements the critical pulse generation logic. This module is optimized for precise timing and low-latency control.

### Blockdiagram

The pulser design is composed of a layered architecture separating register interface logic from the pulse generation core. The diagrams below illustrate both a simplified view and the complete structure of the pulser.

#### Simplified Architecture

The following diagram presents a single `pulser_core` module with its register interface. It shows the implementation with one pulser only for easier understanding.
This structure is **not** implemented and should only help to understand the structure.

![Single Pulser Block Diagram](./doc/bd_single_pulser.svg)

- **periph_to_reg:** Convert OBI to a register request / response.
- **pulser_reg_top:** Register file to store pulser configurations **and** start / stop.
- **pulser_core:** Responsible for pulsing based on configuration inputs.

#### Full System Architecture

The complete system is encapsulated in the `pulser` module, which integrates a configurable number of `pulser_core` instances and corresponding register blocks. It allows for multiple independent pulse channels to be controlled over a shared bus interface.
Each `pulser_core` has it's own register file.
This allows dynamic generation via parameter.
However, it needs a DEMUX / MUX to connect the register request / response to the corresponding register file.
The Blockdiagram shows an integration with `N_PULSER_INST` = 2.
Parts, that are instantiated `N_PULSER_INST`-times are marked blue in the blockdiagram.

![Pulser Block Diagram](./doc/bd_pulser.svg)

- **periph_to_reg:** Convert OBI to a register request / response.
- **pulser_core_reg_top:** Register file to store pulser configurations.
- **pulser_general_reg_top:** Register file to start / stop the pulsers.
- **pulser_core:** Responsible for pulsing based on configuration inputs.

## Reggen

To generate the rtl/pulser_core_reg_top.sv, pulser_core_reg_pkg.sv, rtl/pulser_general_reg_top.sv and pulser_general_reg_pkg.sv files, a regtool is used.

### Generate Registers

Generate systemverilog files
```bash
regtool.py -r -t rtl/ data/pulser_core.hjson
```
Generate c header file
```bash
regtool.py -D data/pulser_core.hjson -o sw/pulser_core_reg_defs.h
```

Generate systemverilog files:
```bash
regtool.py -r -t rtl/ data/pulser_general.hjson
```

Generate c header file:
```bash
regtool.py -D data/pulser_general.hjson -o sw/pulser_general_reg_defs.h
```
